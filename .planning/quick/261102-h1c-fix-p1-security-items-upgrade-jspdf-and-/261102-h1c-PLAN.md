<objective>
Close the two P1 security findings from the 2026-11-02 code review:

1. Direct runtime dependencies sit inside published advisory ranges: `jspdf` (critical, <=4.2.0), `dompurify` (high, <=3.4.16, and it is the SVG-export sanitizer), `zod` (high, <4.6.6, validates URL-supplied groove data) and `react-router-dom` (high, 7.0.0-pre.0 - 7.14.1).
2. The repo ships no Content-Security-Policy. `.htaccess` defers to a root policy outside the repo, and the live header (checked 2026-11-02 against https://www.bahar.co.il/groovy/) carries `'unsafe-eval'` and bare `https:` sources in script-src, style-src and font-src.

Purpose: remove known-vulnerable code from the bundle and give the app a policy scoped to what it actually loads.
Output: patched `package.json`/lockfile, and a `.htaccess` that sets an enforcing CSP for `/groovy/`.

Out of scope (tracked separately): trimming analytics payloads, transitive dev-only advisories (vite, vitest, rollup...), the `X-XSS-Protection` header.
</objective>

<interfaces>
Origins the app loads, by directive (verified by reading the source and the live page/analytics script):

- script-src: self (Vite module bundle, no inline scripts in built index.html);
  https://www.bahar.co.il (`universal-analytics.js`, src/utils/analytics.ts);
  https://cdn.amplitude.com (Amplitude SDK injected by that script via `createElement('script')`).
  No `eval`/`new Function` anywhere in src/ or in the analytics loader.
- style-src: self; 'unsafe-inline' (React `style=` attributes and abcjs-injected styles);
  https://fonts.googleapis.com; https://cdnjs.cloudflare.com (Font Awesome 4.7, src/head.tsx).
- font-src: self; https://fonts.gstatic.com; https://cdnjs.cloudflare.com; data:.
- img-src: self; data: (QR codes, `canvas.toDataURL`); blob: (SVG -> Image in exportImage.ts).
- media-src: self; blob: (drum samples are fetched, so they fall under connect-src; blob: kept for exported audio).
- connect-src: self (sample fetch in DrumSynth.ts/exportAudio.ts);
  https://go.bahar.co.il (urlShortener.ts);
  https://www.bahar.co.il; Amplitude ingest + remote-config hosts for both zones
  (https://api.amplitude.com https://api2.amplitude.com https://api.eu.amplitude.com
   https://sr-client-cfg.amplitude.com https://sr-client-cfg.eu.amplitude.com).
- frame-ancestors: * — the Share modal hands users an `<iframe src=".../?embed=true">` snippet
  (ShareModal.tsx:147, EmbedPage.tsx) for third-party pages, and the live site already allows
  framing (it sends `X-Frame-Options: ALLOWALL`). The repo's `X-Frame-Options: SAMEORIGIN` line
  would break that feature if deployed, so it is replaced by the CSP directive.
- object-src 'none'; base-uri 'self'; form-action 'self'.

Apache note: `Header always set` in `/groovy/.htaccess` replaces the root header for that path,
so the app's policy takes effect without touching the site-wide one.
